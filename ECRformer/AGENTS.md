# ECRformer 작업 및 결과 정리 규칙

- 기본 작업 브랜치는 `research/ecrformer-stable-training`. 새 요청마다 브랜치/PR을 만들지 말고 같은 브랜치에 커밋하고 열린 PR을 갱신한다. 다른 브랜치는 사용자 명시 요청이 있을 때만 사용한다. main 병합은 사용자가 한다.
- ECRformer에서 직접 수정한 파일만 명시적으로 stage한다. `git add .` 금지. 팀원 변경을 포함하지 않는다. Git 작성자 확인과 한국어 커밋 메시지 규칙을 지킨다.
- 학습은 사용자 승인 없이 시작·예약·재개하지 않는다. 활성 학습의 checkout을 pull하거나 실행 코드를 덮어쓰지 않는다. 별도 환경과 변경 범위를 확인한다.
- README에는 완료 test 평가, 같은 조건의 전후 비교 그림, 최근 학습 분석과 다음 실행 상태를 구분해 표시한다. 상세 조건·과거 실험은 docs로 분리한다.
- 새 실험 보고서는 `docs/experiments/template.md`를 사용한다. test/validation, 패치/ROI/독립 장면, 13밴드 지표/표시용 RGB를 구분한다. 조건이 다른 수치로 개선을 확정하지 않는다.
- SAR·cloudy·예측·정답을 동일 패치로 비교한다. 전후 비교에서는 이전 예측을 추가한다. 미래 사례는 수치 확인 전에 5개를 고정하고 경로·ROI/patch ID·seed·순서를 기록한다. 독립 ROI를 확보하지 못하면 한계를 명시한다.
- 없는 과거 곡선·예측·선정 근거·가중치 epoch/해시를 만들거나 추정하지 않는다. 미확보로 표시한다. 규칙은 앞으로의 보고 기준이며 기존 자료가 모두 충족한다고 주장하지 않는다.
- 원본 TIFF, 새 대용량 checkpoint, 전체 NPZ, 원시 로그는 Git에 추가하지 않는다. 기존 보관 자료와 팀원 폴더를 정리·삭제하지 않는다. 숫자 요약·compact curve·소수 비교 이미지와 서버 보관 경로/식별자를 연결한다.
