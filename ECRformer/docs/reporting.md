# ECRformer 결과 정리 기준

[현재 연구](../README.md) · [공통 보고서 양식](experiments/template.md)

SSA-MRN의 간결한 README, 실험 이력, 조건을 붙인 전후 비교와 실제 그림을 참고했습니다. ECRformer는 초해상도가 아니라 구름 제거이므로 입력 패널·밴드·지표·실패 분석을 다르게 구성합니다. 아래는 앞으로의 기준입니다. 이번에는 정리 구조만 추가했으며 자동 exporter·새 평가·추론·그래프 생성 기능을 구현하거나 실행하지 않았습니다.

## 정량 평가

- 평가 분할과 정확한 패치 목록/순서, ROI 수와 독립 장면 여부, 데이터 정규화·crop·TTA·metric 구현 commit을 기록합니다.
- 전체 test의 RMSE·MAE·PSNR·SAM·SSIM과 RGB 기반 LPIPS를 구분해 보고합니다. validation best를 test 결과로 표시하지 않습니다.
- 동일 목록의 이전/현재/차이(현재−이전)를 표시합니다. 조건이 다르면 N/A와 이유를 기록합니다. 구름 입력 baseline은 실제 계산한 경우에만 추가합니다.
- 구름 비율을 분석한다면 마스크·비율 계산 출처와 구간 경계를 고정합니다. 데이터가 없으면 미측정으로 둡니다. 밴드별 MAE/RMSE·분광 곡선은 실제 13밴드 예측을 확보한 경우만 생성합니다.

## 곡선

실제 epoch 기록에서 train loss/MAE, validation loss/PSNR/SAM/SSIM, lr을 그립니다. best와 발산 시점을 표시하고 데이터·장치·실행 중단/재개 이력을 기록합니다. 발산으로 축을 바꾸거나 로그 축을 사용하면 표시합니다. 누락 epoch를 관측값처럼 보간하지 않습니다. 전후 그래프는 서로 다른 test 조건을 섞지 않습니다.

## 이미지와 사례 선택

기본은 **SAR · 구름 입력 · 예측 · 정답** 4패널, 같은 패치의 모델 전후 비교는 **SAR · 구름 입력 · 이전 예측 · 현재 예측 · 정답** 5패널입니다. HSI 초해상도의 LR/RGB 패널을 그대로 복제하지 않습니다.

미래 실행은 성능 수치 확인 전에 5사례를 선택하고 `selection.json`에 seed·데이터 분할·전체 경로·ROI/patch ID·순서를 기록합니다. 가능하면 서로 다른 ROI를 사용하되 부족하면 실제 구성을 기록합니다. 결과를 본 뒤 더 잘 나온 사례로 교체하지 않습니다. 별도 실패 사례를 추가할 때는 선정 기준을 명시합니다.

RGB의 기본 표시 밴드는 0-based `(3,2,1)`입니다. cloudy/이전/현재/정답에 같은 표시 범위·밝기 배율을 적용하고 값을 기록합니다. SAR 밴드와 대비도 명시합니다. 예측만 따로 선명하게 보정하지 않습니다. 모든 밴드 수치는 원래 값으로 평가합니다. RGB 표시용 clip/밝기와 metric 전처리를 구분합니다.

## 보고서와 산출물

각 실행에 `docs/experiments/<experiment_id>.md`를 작성하고 다음 근거를 연결합니다.

| 산출물 | 기록 내용 | Git 보관 |
| --- | --- | --- |
| summary / sample metrics | 전체 평균, 패치별 수치, 평가 설정 | 작고 공개 가능한 숫자 파일만 |
| compact epoch 기록·그래프 | 실제 관측 곡선·lr·best | 작은 수치 파일·그림 |
| selection·비교 이미지 | 고정 사례 목록, 공통 표시 설정 | 경로 공개 범위 검토 후 소수 그림 |
| 가중치·코드 식별자 | 코드 commit, checkpoint epoch·SHA-256, 초기화/재개 방식 | 원본 가중치는 서버, 문서에 위치·해시 |
| 원시 로그·TIFF·13밴드 NPZ | 재분석용 원본 | 서버 보관, Git 제외 |

위 파일명은 미래 산출물 규약이며 지금 존재한다는 뜻은 아닙니다. 기존 `reproduction/` 자료는 이동·삭제하지 않습니다. 미래 가중치 정책을 이유로 기존 tracked 파일을 제거하지 않습니다. 과거 미확보 곡선/선정 manifest/해시는 그대로 미확보로 표시합니다.

## 보고 상태

`준비` → `학습 기록 확보` → `test 평가 완료` → `보고 산출물 확인`을 구분합니다. 종료 코드 0만으로 완료 평가를 선언하지 않습니다. 해석과 가설, 변경 코드와 검증된 효과를 분리합니다. 새 학습·평가는 별도 사용자 요청 이후에만 실행합니다.
