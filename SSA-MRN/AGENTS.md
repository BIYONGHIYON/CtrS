# SSA-MRN PAN–MS 팀 연구 규칙

## 현재 연구 기준

- 2026-10-09 Windows 3센서 validation 다수결에 따라 현재 연구 기본값은 K=4로 확정한다. 별도 승인된 K 비교 외 신규 기준선·개선 비교는 K4로 설계한다.
- 2026-10-20 성능 49번(QB, seed 42·43·44 평균 개선)에 따라 기준 모델을 **F1**(원본 SSA-MRN K4 + 성능 28번 G5 관측 오차 보정기 2개, 코드 `experiments/performance/48_parallel_capacity_observation_refinement/model.py`의 `F1`)로 교체한다. 이후 신규 개선 비교의 대조군은 F1이며, 원본 SSA-MRN K4는 비교 기준으로 보존한다. 이전 실험의 대조군·판정은 바꾸지 않는다. 채택 근거는 QB 결과이며 다른 센서 확인은 하지 않았다.
- 과거 K6 실험의 실제 설정·가중치·수치를 변경하거나 K4 결과로 표시하지 않는다. 실행 중 학습은 문서 정리만으로 변경·재시작하지 않는다.
- 보고서의 비교 조건에서 실제 K, validation/test, 학습/평가/보관 상태를 구분한다. K4 확정을 모든 센서·test 지표의 우위로 확대 해석하지 않는다.

## 연구 분야와 담당

- 연구 안내는 `SSA-MRN/research/ssai/README.md`(SSAI 개선·이병현, 1-12번 정리 완료), `variable_scale/README.md`(가변 배율 확장·김윤지), `performance/README.md`(기존 성능 개선·김경찬·송준현·이병현)로 나눕니다. 세 경로는 `SSA-MRN/research/` 기준입니다.
- 새 SSAI·가변 배율 연구는 계획·실험 미착수로 시작합니다. 주제만 정해진 상태를 실행한 실험으로 등록하거나 빈 가중치·실행 코드 폴더를 만들지 않습니다. 구체적인 실험이 정해지면 계획 상태부터 표에 추가합니다.
- 기존 1-28번은 `performance`의 선행 이력으로 보존합니다. 과거 SSAI 관련 실험은 새 연구에서 참고 링크로 연결하며 새 분담의 완료 실적으로 옮기지 않습니다. 분야 담당자가 바뀌어도 과거 실험자는 변경하지 않습니다.
- 연구 분류는 `research/catalog.json`의 분야 ID를 사용하며, `research/experiments.json`의 각 항목에는 `research_track`와 실제 `experimenter`를 기록합니다. 새 실험은 주된 연구 질문에 따라 한 분야에 등록하고, 다른 분야에서는 참고 링크로 연결합니다.
- 연구 분야 폴더에는 목적·담당·상태·실험 표를 담은 README와 해당 분야의 실험 폴더를 함께 둡니다. 코드·가중치·결과·8절 보고서는 `research/<분야>/<번호>_<변경>/` 한 곳에 보관하고 다른 분야에서는 링크로만 참조합니다.
- 실험 추가·상태 변경 시 해당 연구 페이지와 두 README의 같은 연구 분야 표, experiment catalog를 함께 갱신합니다. 보고서는 첫머리에 연구 분야와 실제 실험자를 표시합니다.
- 새 실험 번호는 각 연구 분야에서 독립적으로 1부터 시작합니다. 번호를 정하기 전 최신 main과 열린 PR에서 해당 분야의 사용 여부를 확인하고, 해당 분야의 새 번호 순서대로 증가시킵니다. 기존 실험의 번호·경로와 실행 중 runtime은 변경하지 않습니다.
- 번호 확인은 실험을 시작할 때 한 번으로 끝내지 않습니다. 커밋, PR 생성, PR 업데이트(push) 직전마다 `git fetch`로 최신 main을 받고 `gh pr list --state open`으로 머지 대기 중인 PR을 다시 확인합니다. 같은 분야의 같은 번호가 main 또는 먼저 올라온 열린 PR에 있으면, 나중에 올리는 쪽이 다음 빈 번호로 폴더·보고서 제목·README 표·`catalog.json`·`experiments.json`·manifest 경로를 함께 바꾼 뒤 올립니다. 서버 runtime 경로와 원본 소스·체크포인트 내부 설정은 바꾸지 않고, 보고서에 작업 당시 번호를 기록합니다.
- SSAI 연구는 바꾼 융합 연산·입력·출력과 원본 대조군을 명시합니다. K와 공간 배율을 구분하며 구조 외 조건이 달라지면 비교의 한계를 기록합니다.
- 가변 배율 연구는 학습/평가 배율, 본/미학습 배율, 입력/출력 크기, 데이터 열화·보간·정렬, 단일/배율별 모델 여부와 배율별 대조군을 명시합니다. 확인하지 않은 배율을 지원한다고 쓰지 않습니다. 배율별 RR·FR과 조건을 분리해 보고합니다.
- SSAI 연구는 2026-10-16 1-12번 결과를 정리했고 신규 실험을 계획하지 않습니다. 다시 시작할 때는 새 가설을 계획 상태부터 등록합니다.
- 기존 성능 개선 연구는 김경찬·송준현·이병현이 이어갑니다. 모든 분야는 validation으로 후보를 선택하고 실제 test 결과로 개선 여부를 판정하며, 다른 조건의 숫자를 무조건 합치거나 새 기준 모델로 자동 승격하지 않습니다.

## 새 결과의 완료 조건

- 전체 독립 test 장면 평가와 장면별 숫자 JSON, 코드 commit, weight epoch/해시를 남긴다.
- 학습 MSE/검증 PSNR·SAM 그래프 및 test baseline 비교 그래프를 반드시 만든다.
- 사전 고정한 서로 다른 RR test 장면 5개를 LR MS · PAN 입력 · 예측 · 정답의 4패널로 저장한다. FR에는 GT를 만들거나 있다고 표시하지 않는다. baseline은 수치 비교에 남기되 이미지 패널에는 넣지 않는다.
- selection에 seed, scene ID, tile, 순서를 기록한다. 결과 수치를 본 뒤 예시를 바꾸지 않는다.
- RR/FR 전체 평가와 가중치 해시, 결과 이미지·곡선의 완전성을 확인한다.
- 없는 과거 곡선/예측/epoch는 만들어내지 않는다. 과거 결과의 예시 수 부족은 보고서에 명시한다.

## 정리

- 다음 실험 시작 전에는 [공통 용량 정리 규칙](../AGENTS.md)을 적용한다. 완료 결과의 보존은 검증 가능한 원격 보관을 뜻하며, 보관·복구 확인이 끝난 이전 실행 폴더의 로컬 중복본은 삭제한다. 현재/재개 예정 실험은 유지한다.

- 원본 데이터 및 공식 submodule을 수정/삭제하지 않는다. 대용량 데이터를 Git에 넣지 않는다.
- 실제 학습된 best/latest 원본 `.pt`도 커밋 대상에 포함하고 checksum, 숫자 결과, compact epoch 기록, 정합 manifest, 결과 그래프·예시를 함께 보존한다. 커밋·푸시는 사용자 요청 시 진행한다.
- 완료된 실험의 학습 JSON, 원시 실행 로그, smoke/random 가중치·산출물, 코드 캐시는 삭제할 수 있다. checkpoint 안의 config는 기존 가중치 평가에 필요하므로 수정하지 않는다.
- 현재/재개 예정인 학습 설정, snapshot, controller runtime, 로그, 가중치는 보존한다. 서버에서 active 상태를 확인한 뒤 완료 run만 정리한다.
- 현재 학습 중인 checkout을 pull하거나 실행 코드를 덮어쓰지 않는다.
- 더 이상 쓰지 않는 benchmark/retrain entrypoint는 제거하되 기존 모델 inference와 지표 구현은 유지한다.
- 관련 없는 checkout·환경·팀원의 파일을 정리하지 않는다.
- 커밋 메시지는 간단한 한국어. 승인된 실험 브랜치에만 push한다. main은 사용자만 변경한다.


## 실험 폴더·파일 관리 규칙

- 모든 새 실험은 `SSA-MRN/research/<분야>/<번호>_<변경한 구조의 영문 이름>/` 하나에 모읍니다. 분야는 `ssai`, `variable_scale`, `performance` 중 하나이며 세 분야에 동일한 네이밍 규칙을 적용합니다. 새 실험 번호는 분야별로 1부터 시작하며 각 분야 안에서 순서대로 증가합니다. 기존 실험 번호는 변경하지 않습니다.
- 폴더 이름은 `<정수 번호>_<소문자 snake_case 영문 변경명>`으로 작성합니다. 예: `ssai/1_cross_band_fusion`, `variable_scale/1_scale_conditioned_restoration`, `performance/1_residual_gating`입니다. 예시는 예약된 번호나 실제 실험이 아닙니다. 서버·센서·시드·K·날짜·담당자 이름은 제목 장식으로 붙이지 않고 설정과 비교 조건에 기록합니다.
- 실험 폴더에는 `README.md`, 필요한 `model.py`, `run.py`, `train.py`, `evaluate.py`, `prepare.py`, `config.json`만 둡니다. 필요하지 않은 빈 파일이나 중복 구현을 만들지 않습니다.
- 가중치는 같은 실험의 `checkpoints/<후보·센서·시드>/best.pt`·`latest.pt`, 숫자·compact 기록·이미지는 `results/`, 학습 당시 원본 소스·설정은 `provenance/`에 보존합니다. 초기 재현 가중치도 예외 없이 해당 실험 안에 둡니다.
- 여러 실험이 실제로 공유하는 데이터 로더·기준 모델·보간·관측·지표·미리보기·평가 도구만 `common/`에 둡니다. 실험 전용 코드를 `src`, `scripts`, `docs/assets`로 다시 분산하지 않습니다. 빈 패키지 초기화 파일은 만들지 않습니다.
- 원본 학습 소스와 체크포인트 내부 설정은 보존 근거이므로 이름 정리를 위해 내용을 바꾸지 않습니다. 현행 코드의 import·경로 변경은 가중치 strict load와 추론으로 확인합니다.
- 데이터 경로는 `data/`로 단순화합니다. `data/processed`, 중복 notebook·txt, IDE 설정, 캐시, 완료된 상세 로그, 재생성 가능한 예측 배열은 추적하지 않습니다. 서버의 원본 데이터와 현재 실행·재개 예정인 파일은 건드리지 않습니다.
- `docs/`에는 연구 설명·문서 양식·구조도만 둡니다. 실험 보고서는 각 실험 README에 작성합니다. 저장소 분리 이력, 이전/현재 파일명 대응표, 삭제 파일 복구 위치, 과거 서버 정리·전송 기록은 독자용 문서에 추가하지 않습니다.
- 새 결과를 보관할 때 `research/experiments.json`과 해당 실험의 `manifest.json`을 갱신합니다. manifest에는 현재 파일 경로·크기·SHA-256을 기록합니다. 보존 해시는 `python SSA-MRN/common/verify.py --experiment <번호>`로 확인합니다. 해시 확인과 실제 성능 재평가는 별개입니다.
- 학습·평가·예시 선택 기준은 유지하고 실제 확인한 결과만 작성합니다. validation 선택을 test 결과로 바꾸지 않습니다. README의 8개 절·시간순 표·합니다체를 계속 사용합니다.
- 큰 폴더 이동은 별도 checkout에서 수행합니다. 실행 중 checkout은 pull·이동·덮어쓰기하지 않습니다. 기존 runtime을 새 코드로 재개하지 않으며 새 실행은 별도 runtime을 사용합니다.

## 신규 계열별 실험 보관

- 사용자 지시에 따라 신규 실험은 `SSA-MRN/experiments/<ssai|variable_scale|performance>/<계열 내 번호>_<변경명>/`에 모읍니다. 각 계열은 독립적으로1부터 증가하며 기존 단일번호 실험과 서버 runtime은 이동하지 않습니다. 보고서·catalog·manifest는 계열과번호를 함께 표시합니다. 새 결과는 `experiments/catalog.json`과 기존 연구목록의 참조를 함께 갱신하며 번호가 겹치는 검증은 `--research-track`을 명시합니다.
