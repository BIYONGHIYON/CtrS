# SSA-MRN PAN–MS 팀 연구 규칙

## 현재 연구 기준

- 2026-10-09 Windows 3센서 validation 다수결에 따라 현재 연구 기본값은 K=4로 확정한다. 별도 승인된 K 비교 외 신규 기준선·개선 비교는 K4로 설계한다.
- 과거 K6 실험의 실제 설정·가중치·수치를 변경하거나 K4 결과로 표시하지 않는다. 실행 중 학습은 문서 정리만으로 변경·재시작하지 않는다.
- 보고서의 비교 조건에서 실제 K, validation/test, 학습/평가/보관 상태를 구분한다. K4 확정을 모든 센서·test 지표의 우위로 확대 해석하지 않는다.

## 문서 작성·폴더 관리 규칙

- 루트 README의 현재 연구 기준·구조·결과 이미지에는 기준 모델만 표시합니다. 진행 중 연구와 개선 후보는 모두 다른 실험 표에 넣으며 별도의 최근 연구 소개를 추가하지 않습니다.
- 루트 기준 모델 결과는 여러 고정 장면을 본문에 표시하고 모델·실제 설정·장면·패널 순서를 설명합니다. 다른 후보의 예측 이미지는 해당 실험 보고서에 둡니다.
- 두 README 실험 표는 과거부터 최근까지 시간순으로 정렬합니다. 같은 날짜는 보고서의 확인된 시각·기록 순서를 사용하고 모르는 날짜를 만들어 적지 않습니다.
- 상태·개선 여부는 단어 중간에서 줄바꿈되지 않도록 작성합니다. 긴 상태는 학습 완료 / 평가 대기처럼 의미 단위로 명시적으로 줄바꿈하고 두 열은 가운데 정렬합니다.

- 루트 README는 연구 소개 → 현재 연구 기준 → 구조도 → 결과 이미지 → 다른 실험 표 → 팀원 순서로 작성합니다. 상세 실행·보관 이력은 넣지 않습니다.
- 실험 이름은 바꾼 연산·구조·손실을 명확하게 설명합니다. Windows, Kaggle, QB, K값은 제목 장식으로 붙이지 않고 비교 조건에 기록합니다. K 비교가 연구 주제일 때도 제목은 내부 특징 차원 비교처럼 작성합니다.
- 두 README의 실험 표는 `실험 | 변경한 내용 | 확인된 결과 | 상태 | 개선 여부`로 통일하고 K 열은 두지 않습니다. 보고서로 직접 연결합니다.
- 상태는 계획 / 학습 중 / 학습 완료·평가 대기 / 학습 완료·일부 평가 / 평가 완료 / 사전 검증 완료로 구분합니다. 실행 중 상태는 마지막 확인 시각을 적습니다.
- 개선 여부는 개선 / 부분 개선 / 개선 없음 / 판단 보류 / 비교 기준 / 성능 비교 아님으로 통일합니다. 주요 RR·FR 지표가 같은 조건에서 함께 개선되어야 개선으로 표시하며, 지표·후보·센서가 엇갈리면 부분 개선으로 표시합니다. validation만으로 최종 개선을 확정하지 않습니다.
- 각 보고서는 template.md의 8개 절을 사용합니다. 첫머리에 변경 내용과 `확인된 결과 | 상태 | 개선 여부` 요약을 적습니다. 바뀐 위치·입력·연산·출력과 대조군을 설명합니다.
- 본문은 합니다·했습니다체를 사용합니다. 범위 표기에 물결표를 쓰지 않고 `1-4`, `1에서 4` 등을 사용합니다. 코드와 경로는 원문을 유지합니다.
- 기반 main SHA·브랜치명·긴 해시·전달 과정은 독자용 본문에서 제외합니다. 복구에 필요한 실제 소스·설정·해시는 원본 manifest와 snapshot에 보존하고 재현 자료 절에서 연결합니다.
- 구조도는 실제 적용된 구조를 명시합니다. 결과 이미지는 본문에 표시하고 입력·출력·정답 순서와 표시 조건을 설명합니다. FR에 정답을 만들지 않습니다.
- .vscode·.idea·OS 메타데이터·캐시·로컬 환경은 추적하지 않습니다. 학습 데이터·가중치·결과·snapshot은 불필요한 파일로 취급하지 않습니다. 다른 작업의 로컬 설정과 실행 중 checkout은 보존합니다.

## 새 결과의 완료 조건

- 전체 독립 test 장면 평가와 장면별 숫자 JSON, 코드 commit, weight epoch/해시를 남긴다.
- 학습 MSE/검증 PSNR·SAM 그래프 및 test baseline 비교 그래프를 반드시 만든다.
- 사전 고정한 서로 다른 RR test 장면 5개를 LR MS · PAN 입력 · 예측 · 정답의 4패널로 저장한다. FR에는 GT를 만들거나 있다고 표시하지 않는다. baseline은 수치 비교에 남기되 이미지 패널에는 넣지 않는다.
- selection에 seed, scene ID, tile, 순서를 기록한다. 결과 수치를 본 뒤 예시를 바꾸지 않는다.
- RR/FR 전체 평가와 가중치 해시, 결과 이미지·곡선의 완전성을 확인한다.
- 없는 과거 곡선/예측/epoch는 만들어내지 않는다. 과거 결과의 예시 수 부족은 보고서에 명시한다.

## 정리

- 다음 실험 시작 전에는 [공통 용량 정리 규칙](../AGENTS.md)을 적용한다. 완료 결과의 보존은 검증 가능한 원격 보관을 뜻하며, 보관·복구 확인이 끝난 이전 실행 폴더의 로컬 중복본은 삭제한다. 현재/재개 예정 실험은 유지한다.

- 원본 데이터 및 공식 submodule을 수정/삭제하지 않는다. 대용량 데이터를 Git에 넣지 않는다.
- 실제 학습된 best/latest 원본 `.pt`도 커밋 대상에 포함하고 checksum, 숫자 결과, compact epoch 기록, 정합 manifest, 결과 그래프·예시를 함께 보존한다. 커밋·푸시는 사용자 요청 시 진행한다.
- 완료된 실험의 학습 JSON, 원시 실행 로그, smoke/random 가중치·산출물, 코드 캐시는 삭제할 수 있다. checkpoint 안의 config는 기존 가중치 평가에 필요하므로 수정하지 않는다.
- 현재/재개 예정인 학습 설정, snapshot, controller runtime, 로그, 가중치는 보존한다. 서버에서 active 상태를 확인한 뒤 완료 run만 정리한다.
- 현재 학습 중인 checkout을 pull하거나 실행 코드를 덮어쓰지 않는다.
- 더 이상 쓰지 않는 benchmark/retrain entrypoint는 제거하되 기존 모델 inference와 지표 구현은 유지한다.
- 관련 없는 checkout·환경·팀원의 파일을 정리하지 않는다.
- 커밋 메시지는 간단한 한국어. 승인된 실험 브랜치에만 push한다. main은 사용자만 변경한다.


## 실험 폴더·파일 관리 규칙

- 모든 새 실험은 `SSA-MRN/experiments/<번호>_<변경한 구조의 영문 이름>/` 하나에 모읍니다. 오래된 순서로 `1_`, `2_`를 붙이며 새 실험은 마지막 번호 다음을 사용합니다. 기존 번호는 재사용하거나 재정렬하지 않습니다.
- 실험 폴더에는 `README.md`, 필요한 `model.py`, `run.py`, `train.py`, `evaluate.py`, `prepare.py`, `config.json`만 둡니다. 필요하지 않은 빈 파일이나 중복 구현을 만들지 않습니다.
- 가중치는 같은 실험의 `checkpoints/<후보·센서·시드>/best.pt`·`latest.pt`, 숫자·compact 기록·이미지는 `results/`, 학습 당시 원본 소스·설정은 `provenance/`에 보존합니다. 초기 재현 가중치도 예외 없이 해당 실험 안에 둡니다.
- 여러 실험이 실제로 공유하는 데이터 로더·기준 모델·보간·관측·지표·미리보기·평가 도구만 `common/`에 둡니다. 실험 전용 코드를 `src`, `scripts`, `docs/assets`로 다시 분산하지 않습니다. 빈 패키지 초기화 파일은 만들지 않습니다.
- 원본 학습 소스와 체크포인트 내부 설정은 보존 근거이므로 이름 정리를 위해 내용을 바꾸지 않습니다. 현행 코드의 import·경로 변경은 가중치 strict load와 추론으로 확인합니다.
- 데이터 경로는 `data/`로 단순화합니다. `data/processed`, 중복 notebook·txt, IDE 설정, 캐시, 완료된 상세 로그, 재생성 가능한 예측 배열은 추적하지 않습니다. 서버의 원본 데이터와 현재 실행·재개 예정인 파일은 건드리지 않습니다.
- `docs/`에는 연구 설명·문서 양식·구조도만 둡니다. 실험 보고서는 각 실험 README에 작성합니다. 저장소 분리 이력, 이전/현재 파일명 대응표, 삭제 파일 복구 위치, 과거 서버 정리·전송 기록은 독자용 문서에 추가하지 않습니다.
- 새 결과를 보관할 때 `experiments/catalog.json`과 해당 실험의 `manifest.json`을 갱신합니다. manifest에는 현재 파일 경로·크기·SHA-256을 기록합니다. 보존 해시는 `python SSA-MRN/common/verify.py --experiment <번호>`로 확인합니다. 해시 확인과 실제 성능 재평가는 별개입니다.
- 학습·평가·예시 선택 기준은 유지하고 실제 확인한 결과만 작성합니다. validation 선택을 test 결과로 바꾸지 않습니다. README의 8개 절·시간순 표·합니다체를 계속 사용합니다.
- 큰 폴더 이동은 별도 checkout에서 수행합니다. 실행 중 checkout은 pull·이동·덮어쓰기하지 않습니다. 기존 runtime을 새 코드로 재개하지 않으며 새 실행은 별도 runtime을 사용합니다.
