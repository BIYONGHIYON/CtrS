# Kaggle B1/B2 100에폭 실행과 재개

`scripts/kaggle_b1_b2_100_resume_one_cell.txt` 전체를 하나의 코드 셀에 붙여 넣는다. QB 데이터 경로는 연결된 데이터셋의 긴 파일명으로 설정되어 있다. GPU T4 두 장에서 B1/B2를 각각 실행하며 GPU 데이터 상주와 GPU 배치 생성을 유지한다. 학습은 100에폭, 학습률 1e-4 고정이다.

첫 실행 전에 Session options의 Persistence를 Files only로 설정한다. 첫 실행은 `REQUIRE_RESUME = False`를 사용한다. Kaggle의 파일 보존 기능이 실제로 설정되었는지는 코드가 확인하거나 보장하지 못한다. 세션을 끝내기 전에 결과와 체크포인트가 보관된 Saved Output을 확보한다.

중단 후에는 `REQUIRE_RESUME = True`로 바꿔 같은 셀을 실행한다. 기존 `/kaggle/working`의 상태를 찾거나, 연결한 Saved Output에서 설정이 일치하는 결과를 찾는다. 여러 결과가 있으면 `RESUME_INPUT`에 의도한 suite 디렉터리의 절대 경로를 지정한다. 체크포인트가 없거나 조건이 다르면 오류로 멈추며 처음부터 학습하지 않는다.

체크포인트는 완료된 배치 경계에서 약 1분 간격과 매 에폭에 저장한다. 모델, optimizer, AMP scaler, 난수 상태, 해당 에폭의 배치 순서와 진행 위치를 함께 저장한다. 정상적인 셀 중단 요청은 배치 완료 후 저장하도록 처리한다. 강제 종료 또는 서버 장애는 마지막으로 저장된 배치부터 재개하며, 저장되지 않은 배치는 다시 계산한다. `latest.pt`가 손상되면 이전 복구본을 검사한다.

첨부된 기존 200에폭 셀의 결과도 소스·데이터·설정과 초기화 증거가 일치하면 새 디렉터리로 가져올 수 있다. 원본을 덮어쓰지 않는다. 100에폭을 넘긴 상태는 보관된 100에폭 이내 체크포인트가 있어야 가져온다. RR/FR 평가 도중 중단되면 평가는 다시 실행될 수 있다.

Kaggle이 삭제한 `/kaggle/working` 파일은 코드로 복구할 수 없다. Files only 또는 별도로 보관한 Saved Output이 필요하다.

검증: 로컬 8개 검사 통과. 단일 셀 및 내장 모델/worker 문법, 텍스트 동일성, 데이터 경로, 완료 배치 건너뛰기, 체크포인트 누락/손상/불일치 처리, FFT 관측식 등을 검사했다. 실제 T4 학습, 실제 PyTorch 체크포인트 가져오기, Kaggle 파일 보존, RR/FR 평가는 이 환경에서 실행하지 않았다.
