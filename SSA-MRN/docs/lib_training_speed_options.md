# LIB 학습 시간 단축 후보 측정

현재 grouped12/K=4/23탭 모델의 설정과 가중치를 유지하고, 별도 메모리 모델로 후보를 측정했습니다.
train 16장면의 고정 네 조각, 총 64패치와 batch 4, float32 GT를 동일하게 사용했습니다.
첫 반복의 시작 비용을 제외했고, GPU 전처리와 보간 조합은 A–B–B–A 순서로 반복했습니다.
OS 파일 캐시는 비우지 않았습니다. 이 결과는 전체 393장면의 epoch 시간과 구분합니다.

| 후보 | 측정 결과 | 해석 |
|---|---:|---|
| 현재 process worker 2 | 64패치 학습 중앙값 6.33초 | 비교 기준으로 사용했습니다. |
| thread 2로 프로세스 전달 제거 | 별도 비교에서 약 4.84초 | 동일 입력과 마지막 loss를 확인했고, 해당 비교에서 약 24% 단축됐습니다. |
| 원본 BIL 순차 읽기 + GPU 회전·분할 | 중앙값 2.14초 | 약 3배 처리량, 약 66% 시간 감소를 확인했습니다. |
| GPU 전처리 + 동일 23탭의 polyphase 실행 | 중앙값 2.02초 | GPU 전처리 대비 약 8% 추가 감소를 확인했습니다. 기존 기준 대비 약 3.1배는 두 실험 간 비교입니다. |
| 204밴드 64→256 보간 연산만 비교 | 약 23.8→8.5ms | 약 2.8배 연산 속도를 확인했으며 전체 학습의 2.8배 향상을 뜻하지 않습니다. |

## 가장 효과가 큰 변경

현재 로더는 204MiB HSI 큐브에서 CPU로 회전·네 패치 복사·flip·배치 조립을 수행하고,
worker 프로세스에서 학습 프로세스로 전달한 뒤 pinned memory에 복사합니다.
GPU 전처리 후보는 원본 BIL을 연속 읽고, 동일 float32 값으로 GPU에 전달하여 회전·분할·공동 flip·LR 생성을 수행했습니다.
RGB 정합과 유효 mask의 의미, 204밴드 GT, 네 조각, 샘플 순서와 유효 배치 4는 유지했습니다.
추가 데이터셋 저장 공간은 사용하지 않았습니다.

전체 RGB/GT/mask 픽셀을 두 장면·여덟 패치에서 기존 로더와 비교해 완전히 일치함을 확인했습니다.
반복 학습의 마지막 loss도 GPU 전처리 단독 후보에서는 기준과 일치했습니다.
23탭 후보는 동일한 계수·주기 경계·삽입 위치를 사용하며, 0을 삽입한 전체 격자 대신 실제 보간이 필요한 위치만 계산했습니다.
CPU 출력·gradient와 CUDA 출력이 float32 허용 오차 안에서 일치했습니다.
조합 후보의 최대 할당 메모리는 약 2,125MiB, 예약 메모리는 약 3,760MiB였습니다.

## 적용 우선순위와 추가 확인

1. 장면 단위 순차 읽기와 GPU 회전·분할을 먼저 학습 백엔드로 연결하는 것이 좋겠습니다.
2. 같은 23탭 필터의 polyphase 실행을 적용하는 것이 좋겠습니다.
3. 고정된 검증 장면을 정합·축소한 float32 캐시로 준비하면 매 epoch의 전처리를 줄일 수 있습니다.
   검증 GT 45개만 저장하면 약 2.24GiB이며 RGB·mask·metadata는 추가로 필요합니다. 이 방법의 시간 단축은 아직 측정하지 않았습니다.

GPU 전처리 후보는 현재 CUDA·고정 네 조각·batch 4 전용 벤치마크입니다.
일반 학습기에 연결할 때는 중단 시 thread 종료, epoch별 flip seed, best 재개, validation 전환과 장시간 메모리를 검증해야 합니다.
전체 데이터는 작은 시험 집합처럼 OS 캐시에 모두 들어가지 않으므로, 큰 장면 집합과 실제 epoch를 비교해야 합니다.
배치·epoch·모델 폭을 줄이거나 GT를 float16으로 저장하는 방법은 학습 조건이 달라져 우선 적용하지 않았습니다.

[상세 측정 기록](./benchmarks/lib_training_speed_candidates.json)을 저장했습니다.
재현용 후보 스크립트는 `benchmark_lib_pipeline.py`, `benchmark_lib_raw_scene.py`, `benchmark_lib_interp23.py`,
`benchmark_lib_combined.py`이며 저장소 루트에서 실행합니다. 학습 가중치를 저장하거나 현재 본학습을 재개하지 않습니다.
동시에 본학습을 실행하면 비교 시간이 달라지므로 별도로 측정해야 합니다.

Windows DataLoader의 spawn·직렬화 동작과 worker/pinned-memory 설정은
[PyTorch 2.7 DataLoader 문서](https://docs.pytorch.org/docs/2.7/data.html#platform-specific-behaviors)를 참고했습니다.
