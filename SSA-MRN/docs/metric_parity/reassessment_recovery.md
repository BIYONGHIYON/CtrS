# MATLAB 일괄 재평가 실행 복구

기존 실행에서 확인한 장애는 평가 파일 부족과 모델 로더 미지원을 혼동한 점, 실패 기록까지 건너뛴 재시도 조건, 오래 실행한 터미널에 종속된 러너, 전송 완료 뒤에만 갱신한 진행 상태였습니다. 이전 MATLAB 작업의 GitHub 오류는 `The self-hosted runner lost communication with the server`이며, 로컬 로그는 정상 종료 기록 없이 끊겼습니다. 프로세스가 종료된 직접 원인은 확정하지 않았습니다.

## 변경한 동작

- 체크포인트마다 독립 Python 프로세스를 사용합니다. 오류 기록은 재시도하고, 버전과 입력·예측 파일 해시가 맞는 성공 기록만 재사용합니다.
- 기존 미지원 126개 후보의 모델 생성 경로를 추가했습니다. 원래 소스의 연산을 유지하고 가중치를 strict load합니다. 관측 커널은 체크포인트의 실제 buffer 크기로 복원합니다.
- Git LFS 포인터만 내려받은 가변 배율 가중치 13개는 실제 파일을 내려받고 LFS SHA-256과 크기를 확인했습니다.
- 가변 배율은 원래 합성 열화·crop·입력 배율을 유지하고 RR만 평가합니다. 실험 23은 원래 GF2 RR의 DN 재척도 조건을 유지합니다. 실험 34는 모델 내부의 bicubic LMS 재생성을 유지합니다.
- Windows에서 소스 문자열을 bytes로 보존해 CRLF 변환에 의한 snapshot 해시 불일치를 방지합니다.
- 입력 파일을 먼저 전송하고 체크섬 확인 뒤 예측 파일을 원자적으로 공개합니다. 파일이 전송 중일 때 MATLAB은 읽지 않습니다.
- MATLAB은 25분 묶음으로 실행합니다. 유한한 일괄 작업 컨트롤러가 다음 묶음을 시작하며, 러너는 터미널과 분리된 프로세스로 실행합니다. 시스템 서비스나 예약 작업을 설치하지 않습니다.
- MATLAB 결과는 contract ID와 전체 장면 수가 맞아야 완료로 계산합니다. 파일별 오류는 별도로 기록하고 다음 파일을 계속 처리합니다.

## 확인 범위

기존 미지원 126개 후보 모두 strict load와 유한한 출력의 forward 검사를 통과했습니다. 중간 점검 당시 실패한 16개도 수정 후 재검사를 통과했습니다. 이 검사는 전체 test 평가 완료를 의미하지 않습니다.

재시도, 손상된 파일 재생성, 오래되거나 장면 수가 부족한 MATLAB 결과 배제의 회귀 테스트 3개를 통과했습니다. 실제 전체 추론과 MATLAB 수치 평가는 별도 실행 중이며, 완료 전까지 기존 실험 보고서의 수치를 교체하거나 검증 완료로 표시하지 않습니다.

## 실행·재개

서버에서 다음 명령은 새 학습을 시작하지 않고 보관 가중치를 평가용으로 추론합니다.

```text
python worker_v2.py --runtime C:/CtrS-matlab-reassessment --data C:/CtrS/SSA-MRN/data/dataset
```

로컬에서는 `common/matlab_reassessment_controller.py`에 `--work`, `--runner`를 지정합니다. 공개 CI에는 원본 데이터나 예측 배열을 업로드하지 않습니다. 실행의 완료 여부와 오류는 `v2/status.json`, `v2/pipeline_status.json`, `v2/records/`, `v2/errors/`로 구분합니다.

검증된 결과만 기존 수치와 교체하며, 가중치·원본 모델 코드·학습 이력은 변경하지 않습니다. 자료 부재와 코드 오류는 별도 상태로 기록합니다.
