## 1. 목적과 상태

서로 다른 장치에서 학습했던 과거 K4/K6 재현의 한계를 보완하고, 같은 환경에서 K와 손실의 효과를 확인합니다. Linux 구조 실험과 별도로 수행하며 구조+손실 결합의 효과를 확정하지 않습니다.

**마지막 직접 확인: 2026-10-09 21:11 KST.** 실시간 상태가 아닌 SSH 확인 기록입니다.

| 실행 순서 | 계획 | 마지막 확인 상태 |
|---|---|---|
| QB K4 / K6 | 각각 100에폭 | 둘 다 완료 |
| GF2 K4 | 100에폭 | 완료 |
| GF2 K6 → WV3 K4 / K6 | 각각 100에폭 | 모두 완료 |
| QB 손실 선별 | 3종 × 3계수 × 30에폭 | spectral·consistency 6개 완료, edge 0.001 학습 중 |
| 최우수 후보 연장 | 30→100에폭, 추가 70에폭 | 대기 |

GF2 K4의 최근 5에폭 평균은 약 236초였습니다. 센서·K·손실에 따라 속도가 달라 전체 종료 시각을 확정하지 않습니다. 당시 컨트롤러·학습 프로세스와 heartbeat 갱신, 실행 소스 해시 일치를 확인했습니다.

## 2. 변경 사항과 평가 조건

| 항목 | 고정 조건 |
|---|---|
| 장치 | Windows · RTX 3060 Ti 8GB · CUDA FP32 · 결정론 설정 |
| 데이터 | QB·GF2·WV3의 기존 train/validation 분할·센서별 정규화·제공 LMS 유지 |
| 최적화 | Adam, 고정 lr `1e-4`, effective batch 32, micro batch 4 |
| 시드 | 42, 모델 초기화와 분리된 DataLoader RNG로 데이터 순서 통제 |
| 기준선 | 3센서 × K4/K6 × 100에폭 = 600에폭 |
| 손실 선별 | 선정 K의 QB에서 spectral / consistency / edge 각각 계수 `0.001 / 0.01 / 0.1`, 9개 × 30에폭 |
| 최종 연장 | 선택 후보의 latest 30에폭에서 100에폭까지 추가 70에폭 |
| 전체 학습량 | **940에폭, 한 번에 한 학습씩 직렬 실행** |

각 보조 손실은 기본 GT MSE에 **하나씩 독립적으로** 추가합니다. spectral은 분광 코사인 손실, consistency는 MTF 관측 일관성, edge는 경계 차분 MSE입니다. micro batch의 gradient를 합산해 32장마다 업데이트합니다. K에 따라 모수 크기가 다르므로 같은 시드라도 가중치 배열 자체가 같다는 뜻은 아닙니다.

### K와 손실을 고르는 기준

1. 센서별 **best validation MSE**로 K4/K6를 비교하고, 센서별 승리 수의 다수결로 K를 선택합니다. 센서 내 동률과 최종 동률은 K4입니다. 센서 간 원시 MSE를 합쳐 선택하지 않습니다.
2. 손실 후보 9개의 30에폭 내 best validation MSE로 후보 하나를 선택합니다. 동률이면 run 이름 순서를 따릅니다. test 수치로 K·계수·가중치를 선택하지 않습니다.
3. 선택 후보의 **latest**에서 모델·Adam·CPU/CUDA RNG·데이터 순서를 복원하고 목표 에폭만 100으로 늘립니다. 30에폭 선별 결과와 가중치는 별도 보존합니다.

선별 결과는 QB 기준선의 같은 30에폭 구간과, 최종 후보는 QB 100에폭 기준선과 비교합니다. 30에폭 이후 늦게 수렴하는 후보를 놓칠 수 있으며 단일 시드의 한계를 기록합니다.

### QB consistency의 관측 조건

[관측 검증 보고서](observation_validation.md)에서 QB TRAIN 17,139패치의 공식 MATLAB MTF 대응을 확인했습니다. 프로파일은 `scripts/observation_profiles/qb.json`이며 SHA-256은 `76f6169d85a210a47cd19452035e2c274e7a975683f699f9982a9ecf65f92f6b`입니다.

학습 패치별 뒤집기 위상을 고정하고 LR 경계 5픽셀을 제외한 내부에서 보조 손실을 계산합니다. 기본 GT MSE는 전체 64×64에 적용합니다. 관측 RMSE 약 `2.24e-13 DN`은 구현 검증값이며 모델 성능 개선량이 아닙니다. GF2·WV3로 같은 프로파일을 임의 확장하지 않습니다.

## 3. 정량 결과

다음은 **validation MSE**이며 RR/FR test 지표가 아닙니다. 두 QB run의 `complete.json`과 100에폭 이력을 확인했습니다.

| QB 기준선 | 완료 에폭 | best validation MSE ↓ |
|---|---:|---:|
| K4 | 100 | 0.0001718618192271821 |
| K6 | 100 | 0.00017216439426722606 |

QB·GF2에서는 K4, WV3에서는 K6가 낮아 다수결 2:1로 **K4를 선택**했습니다. 기준선 6개 전체 수치·곡선·원본 가중치는 [K4/K6 기준선 보고서](windows_k_baselines.md)에 모았습니다. 손실 탐색과 최종 후보의 완료·test 평가 결과는 아직 이 문서에 확보되지 않았습니다.

## 4. 직전 연구와 수치 차이

QB의 best validation MSE 차이(K6−K4)는 약 **+3.026e-7**입니다. PSNR·SAM·test MSE 차이는 평가 결과가 없어 계산하지 않습니다.

과거 A6000/CUDA K4와 Radeon/DirectML K6, Linux 구조 실험은 실행 조건이 달라 이번 통제 비교의 대조군으로 대신 사용하지 않습니다. 각 서버는 자체 기준선으로 해석합니다.

## 7. 가중치와 검증 근거

| 항목 | 실제 서버 경로 또는 기록 |
|---|---|
| 실행 코드 | `C:\CtrS-budget-suite\SSA-MRN` — Git 저장소가 아닌 실행 복사본 |
| 결과·실행 계획 | `experiments\controlled_suite_v2\`, 해당 폴더의 `plan.json` |
| 실행 소스 해시 | 결과 폴더의 `source_hashes.json`, 확인 시 불일치 0개 |
| run별 기록 | `config.json`, `history.jsonl`, `train.log`, `best.pt`, `latest.pt`, `complete.json` |
| QB K4 인계 기록 | 결과 폴더의 `adoption.json` |
| 이전 QB K4 위치 | `C:\CtrS-controlled-suite\SSA-MRN\experiments\controlled_suite_v2\01_QB_k4_s42` |

QB K4의 복사된 6개 파일은 인계 기록의 해시와 일치하고 이전 경로의 파일도 존재함을 확인했습니다. 이는 **별도 원격 백업과 복구 검증 완료를 뜻하지 않습니다.** 이전 폴더는 컨트롤러 인계 인자에도 남아 있으므로 실제 참조·복구 가능성 검증 전에는 삭제하지 않습니다.

기준선 6개 원본 best/latest 12개는 [기준선 보관 보고서](windows_k_baselines.md)에 포함했습니다. 손실 탐색·최종 후보도 완료 후 원본을 커밋 대상에 포함하고, 에폭·SHA-256·코드 버전·전체 평가 JSON·곡선·장면 선택 기록을 함께 남깁니다. 진행 중인 손실·최종 후보의 가중치는 이번 기준선 보관 대상에서 제외합니다. 커밋·푸시는 사용자 요청에 따라 진행합니다.

진행 확인·재개·SSH 독립 실행은 [Windows 실행 안내](../operations/controlled_suite.md)를 따릅니다. `complete.json`은 학습 완료 증거이며 독립 test 평가 완료 증거와 구분합니다.

## 8. 한계와 다음 판단

기준선 6개 완료와 K4 선택을 확인했습니다. 남은 순서는 **손실 9개 선별 → 최종 후보 연장 → 같은 학습량 기준선과 전체 평가 → 가중치·결과 보관**입니다. 개선이 없으면 성공으로 기록하지 않습니다.

단일 변경의 효과를 확인한 뒤 반복 시드·센서 확장·구조 결합을 검토합니다. Linux 결과와 합친 평균이나 구조+손실 효과를 미리 확정하지 않습니다. 실행 중단·재시작·조건 변경·서버 종료는 사용자 요청이 있을 때만 진행합니다.
